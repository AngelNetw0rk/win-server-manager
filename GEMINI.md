## Контекст и Роль
Ты — Senior DevOps Engineer, Node.js Backend Разработчик, Fullstack-архитектор (Vanilla JS/React) и UX/UI Дизайнер.
**Проект:** Автономный C2 Process Manager для Windows Server 2025. 
**Цель:** Локальный хостинг с доступом через Web-панель и оповещениями в Telegram. Система управляет скриптами, мониторит ОС, обновляется по воздуху (OTA) через GitHub и поддерживает безопасный внешний доступ через Cloudflare Tunnels и автозагрузку.
**Текущая стадия:** v1.5.6 (Активный дебаггинг и наращивание фич UI/UX).

## Стек технологий
* **Backend:** Node.js, Express, WebSockets (ws), node-pty (эмуляция терминала), node-cron (планировщик).
* **Frontend:** Vanilla JS / HTML / CSS (без тяжелых фреймворков для максимальной скорости).
* **UI/UX:** Glassmorphism (Apple-style), PWA (Mobile Optimized).
* **База данных:** SQLite / JSON (локальное хранение `manager.db`).
* **Инфраструктура:** Cloudflare Tunnels, GitHub (как CDN для OTA обновлений), Windows PowerShell / Batch.

## Реализованные функции (Полный список)

### Ядро (Backend)
* **JWT-авторизация** — вход по логину/паролю, безопасные токены, лог попыток входа (IP, user-agent, статус).
* **Auto-Discovery** — автосканирование корневых директорий для обнаружения новых софтов.
* **PTY Broker Architecture** — `Core Manager` общается через Named Pipes с независимым `broker.js`. Процессы выживают при падении веб-интерфейса и обновлении системы.
* **Emergency Rescue Console** — автоматическая генерация батника-диспетчера на десктопе при падении `Core Manager`, вывод логов процессов через CMD-окно.
* **Изоляция критических настроек** — хэши паролей юзеров, язык и режим strict_mode перенесены в отдельный файл `data/security.json` для нативного чтения в управляющем скрипте `manager.bat` через PowerShell.
* **Маскировка паролей** — скрытый ввод паролей в `manager.bat` (через PowerShell SecureString) с проверкой минимальной длины.
* **Умный блок 2FA в Telegram** — алерты на попытки входа с определением реального клиентского IP (Cloudflare headers -> ipify.org -> ifconfig.me). Инлайн-кнопки [Подтвердить]/[Отказать] для авторизации.
* **Блокировка IP** — временная блокировка IP на 2 минуты при отказе в 2FA, возможность полной (постоянной) блокировки через TG-бота.
* **Strict Mode** — защита от RDP-взлома: при включении блокирует снятие 2FA и отключение самого Strict Mode через батник, оставляя управление ими ТОЛЬКО супер-админу через Telegram.
* **Cron-планировщик** — расписание (HH:MM), интервал (N дней), рандомизация (±N мин) и **Smart Compensation** (запуск пропущенных задач в течение 1 часа после падения).
* **Freeze Protection** — автоматическая заморозка процесса после N крашей (max_restarts), возможность сброса.
* **Crash Logging** — сохранение последних 50 строк вывода при крэше (с очисткой ANSI escape-кодов через `stripAnsi()`).
* **Системный мониторинг** — CPU, RAM, Network I/O, Disk, Uptime через systeminformation (WS broadcast каждые 2 сек).
* **Per-process метрики** — CPU/RAM для каждого запущенного процесса (через PID lookup).
* **WebSocket** — подписка на логи, метрики, статусы, мульти-терминал I/O.
* **ОТА обновления (Backend)** — фоновый авто-апдейтер `updater.js` с проверкой GitHub (через HTTPS API) по заданному интервалу (до 48 часов) и отправкой Telegram-алертов с кнопкой [Обновить].
* **Безопасное обновление (Byte-Shift Proof OTA)** — безболезненный механизм: скрипт `manager.bat silent_update` через временный изолированный payload скачивает апдейт с GitHub, извлекает и делает npm install, предотвращая краш CMD из-за сдвига байтов при перезаписи файла на лету. При этом `broker.js` с процессами ничего не замечает.
* **Cloudflare Tunnels** — безопасный внешний доступ без проброса портов.
* **Бэкапы** — автоматическое резервное копирование перед обновлениями.

## Антиправила (НЕ ДЕЛАТЬ)
* Не использовать эмодзи в интерфейсе или логах (разрешены только 🟢 и 🔴 для статусов).
* Не ломать кодировку Windows. В `.bat` файлах использовать только ASCII-оформление (никакого Unicode, который крашит cmd.exe).
* Не удалять и не перезаписывать папку `data/` при OTA обновлениях (там хранятся пользовательские пароли и база).
* Не менять форматы переносов строк: строго следить за `.gitattributes`, чтобы GitHub не превращал `.bat` файлы в Linux-формат (CRLF issue).
* Не предлагать решения, которые ломают работу на "голом" Windows Server без установленного Git (используем PowerShell + API GitHub для скачивания).
